Context & Data Access

Every template executes against a context. The context represents the data available to the template during rendering and serves as the source of all identifier resolution.

Unlike many template engines, Mutor does not require explicit context prefixes. Properties supplied to the renderer can be referenced directly, allowing templates to remain concise while maintaining strict isolation from the surrounding runtime environment.

Context Values

Context is the value passed alongside a template during rendering. Any JavaScript value can be used as a context, although objects are generally recommended because they provide the cleanest access pattern. 

// Object context
const html = mutor.render(
  template,
  {
    user: {
      name: "Victor"
    }
  }
);

Object properties become available directly within the template.

// Property access
\{{ user.name }}

// Nested property access
\{{ user.profile.avatar }}

// Array access
\{{ users[0].name }}

// Dynamic access
\{{ user[field] }}

Context is not limited to objects. Strings, arrays, numbers, booleans, null values, and any other JavaScript value may also be supplied when appropriate. 

// String context
mutor.render(template, "Hello World");

// Array context
mutor.render(template, [1, 2, 3]);

// Null context
mutor.render(template, null);

Context Resolution

Mutor resolves identifiers against the supplied context automatically. Properties can therefore be referenced directly without requiring explicit prefixes such as ctx or it. 

// Direct property access
\{{ user.name }}

Conceptually, the expression above behaves similarly to:

ctx.user.name

This design keeps templates concise while ensuring that access remains confined to the supplied context and registered namespaces.

Direct Context Access

In situations where the original context value must be accessed directly, Mutor provides Mutor::$$context.

The syntax is intentionally loud. Accessing the root context should be immediately visible when reading a template. 

// Access the original context value
\{{ Mutor::$$context }}

This is particularly useful when rendering against primitive values or other non-object contexts. 

// Render using a string as the context
mutor.render(template, "Hello World");

// Access the string context directly
\{{ Mutor::$$context }}

Runtime Errors

Property access, function calls, and expressions are evaluated at runtime. Invalid property access, calling non-callable values, or any other runtime failure will result in an error being thrown during rendering.

Errors originating from context functions are propagated unchanged. Mutor does not wrap, modify, or reinterpret exceptions thrown by application code. 

const context = {
  getUser() {
    throw new Error("User lookup failed");
  }
};

If the function throws, the original error is returned as-is.

Runtime errors currently do not include template location tracking. Mutor does not yet provide source mapping or execution tracing capable of identifying the exact template location responsible for a runtime failure.

Compilation errors are different. Mutor ships with compilation error tracking and detailed diagnostic messages designed to help identify and resolve issues before a template is executed.

More information can be found in the Errors documentation.
