Syntax Guide

Mutor.js uses a familiar template syntax built around expressions, control structures, and reusable components. Templates remain HTML-first while providing access to safe JavaScript-compatible expressions and built-in Mutor functionality.

Expression Rules

Mutor expressions are intentionally restricted. Templates can read values, access properties, call functions, and evaluate expressions, but cannot create new runtime structures or mutate state.

✓ Allowed 
<!-- Property access -->
\{{ user.name }}

<!-- Index access -->
\{{ users[0] }}

<!-- Function calls -->
\{{ formatPrice(product.price) }}

<!-- Arithmetic -->
\{{ subtotal + tax }}

<!-- Logical expressions -->
\{{ isAdmin && user.active }}

<!-- Optional chaining -->
\{{ user.profile?.avatar }}

<!-- Nullish coalescing -->
\{{ user.bio ?? "No bio" }}

<!-- Existing context object -->
\{{ Mutor::include("./pager.html", pagination) }}

<!-- JSON-generated object -->
\{{ JSON::parse('{"title":"Hello"}') }}
✗ Not Allowed 
<!-- Object literal -->
\{{ { title: "Hello" } }}

<!-- Array literal -->
\{{ [1, 2, 3] }}

<!-- Assignment -->
\{{ total = subtotal + tax }}

<!-- Arrow function -->
\{{ x => x * 2 }}

<!-- Function literal -->
\{{ function() {} }}

<!-- Constructor -->
\{{ new Date() }}

<!-- Inline include context -->
\{{ Mutor::include("./card.html", { title: "Hello" }) }}

<!-- Runtime object creation -->
\{{ { name: user.name } }}

JSON::parse()

Mutor does not support object or array literals directly. If you need to create an object or array inside a template, you can use JSON::parse().

This should be used sparingly. Parsing JSON introduces additional work during rendering and excessive usage can negatively impact template performance. Whenever possible, prepare data in your application code and pass it through the rendering context instead.

Comments

Comments are ignored during rendering and never appear in the final output. They can be used to document templates, leave notes for other developers, or temporarily disable sections of template code. 

<!-- Basic comment -->
\{{# This comment is removed during rendering }}

<!-- Multi-line comment -->
\{{#
  This content can span
  multiple lines and will
  not appear in the output.
}}

<!-- Left whitespace trimming -->
\{{~# This comment trims whitespace on the left }}

<!-- Right whitespace trimming -->
\{{# This comment trims whitespace on the right ~}}

<!-- Trimming on both sides -->
\{{~# This comment trims whitespace on both sides ~}}

Escaping Template Tags

Template tags can be escaped to prevent Mutor from evaluating them. By default, Mutor uses \ as the template escape character.

Escape detection is based on the number of consecutive escape characters immediately before a template opening tag. An odd number of escape characters escapes the tag, while an even number does not. 

<!-- Escaped (1 escape character) -->
\\{{ user.name }}

<!-- Not escaped (2 escape characters) -->
\\\{{ user.name }}

<!-- Escaped (3 escape characters) -->
\\\\{{ user.name }}

<!-- Not escaped (4 escape characters) -->
\\\\\{{ user.name }}

<!-- Whitespace breaks escape detection -->
\ \{{ user.name }}

The escape character can be customized through Mutor's configuration system. Several other parser and compiler behaviors are also configurable. See the Configuration guide for the complete list of available options.

Interpolation

Output values directly into your templates using interpolation tags. Mutor supports property access, index access, arithmetic operations, function calls, optional chaining, nullish coalescing, and other safe expressions. 

<!-- Property access -->
<p>\{{ user.name }}</p>

<!-- Index access -->
<p>\{{ users[0].name }}</p>

<!-- Arithmetic expressions -->
<p>\{{ product.price * 1.1 }}</p>

<!-- Nullish coalescing -->
<p>\{{ user.bio ?? "No bio provided." }}</p>

<!-- Function calls -->
<p>\{{ formatPrice(product.price) }}</p>

Conditionals

Render content conditionally using if, else if, and else blocks. 

\{{ if user }}
  <p>Welcome back, \{{ user.name }}</p>
\{{ else if guest }}
  <p>Browsing as guest</p>
\{{ else }}
  <p>Please sign in</p>
\{{ end }}

Loops

Iterate over arrays, iterables, and object properties using Mutor's loop syntax. 

<!-- Array iteration -->
<ul>
\{{ for product of products }}
  <li>\{{ product.name }}</li>
\{{ end }}
</ul>

<!-- Object iteration -->
\{{ for key in settings }}
  <p>\{{ key }}: \{{ settings[key] }}</p>
\{{ end }}

Loop Metadata

Access information about the current iteration through Mutor::iter. The index property contains the index of the current loop cycle and is only meaningful while executing inside a for...of loop. 

<ul>
\{{ for product of products }}
  <li>
    \{{ Mutor::iter.index + 1 }}. \{{ product.name }}
  </li>
\{{ end }}
</ul>

Includes

Split large templates into smaller reusable files using Mutor::include().

When the context argument is omitted, the included template inherits the current rendering context automatically. You could also access the current rendering context through Mutor::$$context. 

<!-- Inherit parent context -->
\{{ Mutor::include("./header.html") }}

<!-- Pass the current context explicitly -->
\{{ Mutor::include("./pager.html", Mutor::$$context) }}

<!-- Pass an existing object -->
\{{ Mutor::include("./pager.html", pagination) }}

<!-- Generate context using JSON::parse() -->
\{{ Mutor::include(
  "./card.html",
  JSON::parse('{"title":"Featured Product"}')
) }}

Async Templates

Enable asynchronous execution when working with promises, database queries, APIs, or other asynchronous operations. This functionality only works when rendering is done using renderAsync, renderAsyncComponent, or renderFileAsync, depending on the environment you code is to be run.

Async mode is only required when using Mutor::await() or rendering expressions that depend on promises. 

<h1>
  \{{ (Mutor::await(getUser())).name }}
</h1>
