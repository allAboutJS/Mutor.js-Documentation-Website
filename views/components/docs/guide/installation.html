Installation & Setup

Mutor.js distributes separate build targets to match specific runtime contexts. Choosing an entry point dictates the availability of internal I/O methods versus client-side component caching interfaces.

Browser CDN Target

Loads via standard script tag execution. Instantiates a global class constructor directly on the window object. This bundle excludes Node fs bindings and includes the client component registration pipeline. 

<!-- Target script injection -->
<script src="https://cdn.jsdelivr.net/npm/mutorjs@latest/dist/index.js"></script>

<script>
  // Global scope instantiation
  const engine = new Mutor();

  // Component compilation and cache assignment
  engine.registerComponent("user-card", "<div>{{ name }}</div>");

  // Execution pass
  const output = engine.renderComponent("user-card", { name: "Victor" });
</script>

Server Module Target (Node.js/Backend)

Explicit backend distribution containing direct structural hooks to the host operating system's filesystem via native Node paths. registerComponent and renderComponent evaluations are stripped from this execution path. 

// System level isolated file scope entry import
import Mutor from "mutorjs/server";

const engine = new Mutor();

// Synchronous File System I/O execution
const htmlSync = engine.renderFile("./templates/index.mutor", { key: "home" });

// Asynchronous non-blocking Promise filesystem evaluation
const htmlAsync = await engine.renderFileAsync("./templates/index.mutor", { key: "home" });

API Availability

Method Signature Browser CDN (`dist/index.js`) Standard Import (`mutorjs`) Server Import (`mutorjs/server`)
render(template, data) Supported Supported Supported
renderAsync(template, data) Supported Supported Supported
registerComponent(name, template) Supported Supported Not Available
renderComponent(name, data) Supported Supported Not Available
renderFile(path, data, options) Not Available Not Available Supported
renderFileAsync(path, data, options) Not Available Not Available Supported
